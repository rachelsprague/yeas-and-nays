# Pick the next board item

Several sessions may work in this repo at once. This skill picks one item
that no one has claimed and that is unlikely to collide with work in
flight, confirms it with the user, then claims it under the rules in
CLAUDE.md > Backlog > Claiming items. An optional argument narrows the
pick: `priority` (Next only), `quick` (quick wins only), or a word to
match against item text.

## 1. Start from the main checkout

Run this skill from the main checkout, before entering a worktree:
`BOARD.md` and `backlog/` are gitignored, so they exist only there, and a
session isolated in a worktree can't inspect other worktrees (step 2). If
this session is already in a worktree, finish or leave it first. Read
`BOARD.md`, and CLAUDE.md's claim rules if they aren't already in context.

## 2. Map work in flight

Collect the files other sessions are changing:

```
git worktree list
# for each worktree other than your own:
git -C <path> diff --name-only main...HEAD
git -C <path> status --porcelain
# and the main checkout's own uncommitted changes:
git -C <main checkout> status --porcelain
```

Ignore `data/out/` (regenerated by CI) and gitignored files. Match each
worktree to a claim in Now by alias or branch name where you can. A claim
with no worktree diff yet still counts: estimate from its item text (and
its `backlog/<slug>.md`, if linked) which files it will touch, e.g. a
member-profile item touches the member export and `site/` member layout.

## 3. List candidates

- **Priority:** items in Next.
- **Quick wins:** items in Later that are small and self-contained: a
  one-place fix, a test to add, a comment or doc correction, a config line.
  Not features, design passes, or anything needing a new data source.

Drop any item that is:

- claimed by anyone, or in Blocked;
- waiting on a date or a condition that hasn't been met ("after a few
  days of…", "by 2027-…" not yet due);
- mostly a decision for the user ("decide…", "consider…") or an action
  outside this repo (renewing a token, setting up another project);
- likely to touch the same files as work in flight (step 2). Find the
  files by grepping for paths, functions, and terms the item names.

Prefer Next over Later when both are clear. Among equals, prefer the item
listed first, and items whose details are already written down.

## 4. Propose and confirm

Tell the user the pick in a few lines: the item, why it's next, the files
it likely touches, and any overlap you couldn't rule out. Name one or two
runners-up. If nothing qualifies, say why (all claimed, all overlap,
all need a decision) and stop.

Then ask the user to confirm the pick or choose a runner-up
(`AskUserQuestion`, with the pick first and marked recommended). Don't
claim, edit, or enter a worktree until they answer.

## 5. Claim

Claim the item the user chose:

1. If you have no alias yet this session, pick one short lowercase word not
   used in any claim on the board and tell the user.
2. Re-read `BOARD.md` right before editing. If the item was claimed while
   the user was deciding, say so and go back to step 3.
3. Move the item to Now and append
   ` — claimed by **<alias>** (YYYY-MM-DD HH:MM local, from <column>)`.

## 6. Start

Read the item's `backlog/<slug>.md` if it has one, then enter a worktree
on its own branch (`<alias>/<short-slug>`) before the first edit, and
explain the approach before any significant change.
